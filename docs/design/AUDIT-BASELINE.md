# CDM Portal — Baseline Design Audit (7 Layers)

> Generated by Uma (UX Design Expert) on 2026-05-06.
> Method: redesign-skill 7-layer diagnostic against the live `aiox-dashboard` codebase.
> Scope: read-only static analysis of `src/styles/`, `src/components/ui/`, `src/components/layout/`, `tailwind.config.ts`, top-level feature components.
> Status: **baseline** — captures as-is state. Findings are inputs to a remediation backlog, not a verdict.

---

## Severity legend

| | Meaning |
|---|---|
| **CRIT** | Breaks the system identity or accessibility. Fix before next release. |
| **HIGH** | Inconsistency that compounds; blocks future work or theme additions. |
| **MED** | Real issue but contained. Fix in normal cadence. |
| **LOW** | Polish / nice-to-have. |

## Layer 1 — Typography

### Findings

| # | Sev | Finding |
|---|---|---|
| T1 | HIGH | Default theme has **no display face** — `--font-family-display` aliases to `--font-family-sans`. Only AIOX Cockpit theme actually uses TASAOrbiterDisplay. The brand identity collapses to "system sans" outside cockpit theme. |
| T2 | MED | `--font-size-md` (0.8125rem / 13px) sits **between** `sm` (12px) and `base` (14px). A non-monotonic scale invites accidental misuse — designers reach for "medium" and get smaller-than-base. Either remove or rename. |
| T3 | MED | Type scale has a 16px gap between `lg` (16px) and `xl` (24px), then a 16px gap between `xl` (24px) and `2xl` (40px), then a 24px gap to `display` (64px). Not a consistent ratio (no 1.25 / 1.333 / 1.5 progression). Composition decisions become ad-hoc. |
| T4 | MED | Letter-spacing tokens are correct but **not paired with size guidance**. There is no guidance like "use `--letter-spacing-wider` only with `--font-size-sm` labels". Spacing applied to display sizes inflates width unpredictably. |
| T5 | LOW | Mono font stack is generic (`'SF Mono', 'Fira Code', 'Cascadia Code', Consolas, monospace`). AIOX theme overrides to Roboto Mono — but default theme has no fallback for the "labels in mono" pattern that already exists in the Cockpit components. |
| T6 | LOW | No line-height tokens at all. Each component invents its own. |

### Recommendations

- Add a real default display face (or accept that default theme has none, and document it).
- Remove or rename `--font-size-md` to avoid the non-monotonic gap.
- Add `--line-height-{tight,base,relaxed}` tokens.
- Document letter-spacing × size pairings (e.g., a small caps spec).

## Layer 2 — Color & Surfaces

### Findings

| # | Sev | Finding |
|---|---|---|
| C1 | HIGH | Default Liquid Glass theme uses `--palette-blue-800` (#007aff) as `--color-accent`. This is exactly the "purple/blue AI gradient" register the brand explicitly rejects in PRODUCT.md. The default theme contradicts the brand. |
| C2 | HIGH | **Two competing accent stories:** default theme says blue is the accent; AIOX theme says lime. New components built in default theme make blue feel canonical — then break visually when AIOX takes over. |
| C3 | HIGH | AIOX `aiox.css` Tier 5b (lines ~610–700) globally remaps Tailwind utility colors (`text-blue-*`, `bg-purple-*`, etc.) to brandbook hues using attribute selectors. This works but is **fragile**: any new utility shade or selector pattern bypasses it silently. The fix is to forbid these utilities, not patch them. |
| C4 | HIGH | Squad palette identity is **theme-dependent**. Default uses 11 distinct hues (purple/blue/orange/pink/green/cyan/teal/red/indigo/yellow/gray). AIOX collapses to 4 brandbook families (lime / blue / flare / gray). The same squad has different identity depending on theme. |
| C5 | MED | `kanban-priority-medium` and `kanban-priority-high` semantics differ between themes (default: blue/orange; AIOX: gray/lime). "Medium priority" is rendered differently — the operator's mental model breaks across themes. |
| C6 | MED | Pure `#000000` is referenced in Tier 4/5 overrides (`bg-black/80`, `bg-black/50`). Brand says use `#050505`. Some legacy spots still use `#000000`. |
| C7 | MED | Status muted variants exist (`--color-status-success-muted`, etc.) but no formal rule for when to use full vs muted. Components decide ad-hoc. |
| C8 | LOW | Dark surface stack `--palette-dark-{500..900}` is defined but only used in default-dark; AIOX uses bespoke `oklch(...)` values. Two parallel surface stacks. |
| C9 | LOW | No documented contrast pairs. Need a contrast matrix (`docs/design/contrast-matrix.md`) showing every fg/bg pairing in use, with WCAG AA verdict. |

### Recommendations

- **Pick one accent for default theme** that aligns with brand, or stop calling Liquid Glass the brand identity (treat it as a guest theme, AIOX as canonical).
- Eliminate Tier 5b remap by enforcing token-only color usage (lint rule).
- Define squad colors in **one** semantic mapping; let themes shift hue, not identity.
- Standardize priority-color semantics across themes.
- Replace any `#000000` literal with `--aiox-dark` / `var(--palette-dark-900)`.
- Add contrast matrix and WCAG AA gate in CI.

## Layer 3 — Layout

### Findings

| # | Sev | Finding |
|---|---|---|
| L1 | HIGH | **Two spacing scales coexist**: `--spacing-{1..4}` (Tailwind-ish 4–16px) and `--space-{0..13}` (brandbook 14-step). Tailwind exposes only the brandbook one as `bb-*`. Components use both. There is no migration plan. |
| L2 | HIGH | `--space-4` is **15px** (brandbook), not 16px. Legacy components built around 16px / `1rem` will not align to brandbook rhythm. The ~1px offset compounds visually in dense layouts. |
| L3 | MED | No grid system documented. Layouts hand-roll columns. Density-first product needs an explicit grid (12 or 16 col) and gutter rules. |
| L4 | MED | Sidebar / header / activity panel widths are not exposed as tokens. They live in component CSS / Tailwind utilities. Theme variants cannot resize the shell. |
| L5 | MED | Z-index scale exists (`base...toast`) but there's no `popover` or `tooltip` tier between `dropdown` (200) and `overlay` (300). Popovers in some components use 250 (hand-rolled). |
| L6 | LOW | No breakpoint tokens. Tailwind defaults are used implicitly. Mobile/tablet behavior is ad-hoc. |

### Recommendations

- Deprecate `--spacing-*` in favor of `--space-*`. Codemod or migration table.
- Decide: keep brandbook 15px or move to 16px (consistency with `1rem`). Document either way.
- Add `--layout-{sidebar-width,header-height,activity-panel-width}` tokens.
- Add `popover: 250` and `tooltip: 350` to z-scale.
- Define explicit breakpoints (`sm`, `md`, `lg`, `xl`, `2xl`) as tokens.

## Layer 4 — Interactivity & States

### Findings

| # | Sev | Finding |
|---|---|---|
| I1 | CRIT | **No standardized focus ring across themes**. Default theme uses `--color-border-focus: rgba(blue, 50%)`. AIOX uses `rgba(lime, 50%)`. Some components define their own ring color via Tailwind (`focus:ring-blue-500`). Keyboard users see inconsistent rings. |
| I2 | HIGH | **Hover states are not systematic.** Some components transform (`translateY(-1px)`), some change border, some change background, some glow, some do nothing. No documented hover taxonomy by component class (atom / molecule / organism). |
| I3 | HIGH | **Disabled state visual is weak**: `--color-background-disabled` is `rgba(black, 3%)` (default) — barely distinguishable from base. Disabled buttons are easy to miss-click. |
| I4 | MED | **Loading state inconsistency**: `Skeleton`, `PageLoader`, `CockpitSpinner`, `[class*="animate-spin"]` overrides — four loading vocabularies. No rule for which to use when (`Skeleton` for content shape vs spinner for indeterminate work). |
| I5 | MED | **Active vs Selected semantics**: `--color-background-active` (button press) vs `glass-card-active` (selected card) vs `kanban-priority-*` (priority highlight) overlap. Operators can't tell at a glance what is "active right now" vs "currently selected in list" vs "highlighted by priority". |
| I6 | MED | Reduced-motion respected only in AIOX theme block. Default theme animations and transitions still run when `prefers-reduced-motion: reduce`. |
| I7 | LOW | No "loading" state for buttons across themes consistently — `CockpitButton` has it, `GlassButton` may not. Verify and unify. |
| I8 | LOW | No empty-state taxonomy. `EmptyState` component exists but its variants (no data / no permissions / first-time / error / search-empty) are not enumerated. |

### Recommendations

- One focus-ring token, one rule: every interactive element gets `:focus-visible` ring of `--color-border-focus` × 2px (or 3px for cockpit).
- Document hover taxonomy: "atoms get color shift, molecules get elevation + border, organisms get shadow + transform".
- Strengthen disabled state to include opacity 0.4 + cursor-not-allowed + reduced contrast.
- Pick one loading vocabulary per case (skeleton for content, spinner for indeterminate, progress for known duration).
- Add `prefers-reduced-motion` block to default theme.

## Layer 5 — Content & Copy

### Findings

| # | Sev | Finding |
|---|---|---|
| Co1 | HIGH | No documented voice/tone guide in the codebase. PRODUCT.md (this baseline) is the first attempt. |
| Co2 | HIGH | **Bilingual surface (PT/EN/ES/ZH) but no i18n discipline visible.** No central `i18n/` folder with key catalog; copy is likely scattered. (Verify: search for `useTranslation` / locale files.) |
| Co3 | MED | Generic placeholders likely present (`"Loading..."`, `"Something went wrong"`, `"Welcome"`). These violate the "honest, specific" voice. Need a copy audit pass. |
| Co4 | MED | Status messages probably mix imperative and report tones. Need a styleguide enforcing report-tone for system messages. |
| Co5 | LOW | Storybook stories are excellent for visual contracts but rarely document **copy** examples. Add "Copy" knobs / variants to canonical story files. |

### Recommendations

- Write `docs/design/voice-tone.md` with do/don't examples.
- Audit all string literals; centralize into i18n catalog if not already.
- Forbid `"Loading..."` and `"Something went wrong"` via lint pattern.
- Add a "copy" tab to Storybook for top-10 components.

## Layer 6 — Components (genericity)

### Findings

| # | Sev | Finding |
|---|---|---|
| Cm1 | HIGH | **Cockpit components are theme-coupled** (only render correctly with `data-theme="aiox"` because they use inline styles with `--aiox-*` vars). Default theme renders them as un-styled or partially styled. They are not portable. |
| Cm2 | HIGH | `GlassButton` / `GlassCard` / `GlassInput` use **liquid-glass aesthetic by default** — translucency, blur, rounded corners. Cockpit theme overrides via global selector hacks (`html[data-theme="aiox"] .glass-card`). The component is named for one theme but lives across all. |
| Cm3 | MED | `Badge` exists but `CockpitBadge` is a parallel implementation. **Two badge components.** Same for spinner (`PageLoader` vs `CockpitSpinner`), KPI (no canonical, only `LiveMetricCard` + `CockpitKpiCard`), alert (no canonical, only `CockpitAlert`). |
| Cm4 | MED | Component variants are inconsistent across families: `GlassButton` (3 variants?), `CockpitButton` (4 variants × 3 sizes). Need a unified variant taxonomy. |
| Cm5 | MED | **Icon usage is generic**: `lucide-react` is the only icon source. No brand-specific iconography. PRODUCT anti-pattern says "generic Lucide-only" should be avoided — needs at least a curated icon-map and 5–10 brand-specific glyphs (HUD brackets exist, but as CSS not SVG). |
| Cm6 | LOW | No documented "atoms vs molecules vs organisms" taxonomy. Components are organized by feature folder, not by atomic level. |
| Cm7 | LOW | `__tests__` and `.stories.tsx` parity is inconsistent — some primitives have stories but no tests, others vice versa. |

### Recommendations

- Rename "Glass*" → "Default*" (or theme-neutral) and decouple aesthetic from base.
- Merge `Badge` + `CockpitBadge` into one `Badge` with theme-driven variants.
- Same for Spinner, KPI, Alert.
- Build a curated icon map (`src/components/ui/icons/icon-map.ts` style — see core lib).
- Add atomic-design folder structure or at minimum a doc mapping current components to atomic levels.
- Enforce parity: every primitive has both `.stories.tsx` and `__tests__/`.

## Layer 7 — Code Quality

### Findings

| # | Sev | Finding |
|---|---|---|
| Q1 | HIGH | `aiox.css` is **1200+ lines** with multiple Tier sections (1, 2, 3, 4, 5, 5b, 6, etc.). Single-file gravity. Should be split per-concern (component overrides, pattern utilities, animations are already split, but Tier 5b remap belongs in its own file or — better — eliminated). |
| Q2 | HIGH | `!important` is used heavily (~150 instances in `aiox.css`) to win specificity vs Tailwind utilities. This is symptomatic of Q1/C3 — fix the root (don't use Tailwind utility colors), not the symptom. |
| Q3 | MED | Token validation script exists (`npx tsx scripts/validate-brandbook-tokens.ts`) but is not wired into pre-commit / CI by default. |
| Q4 | MED | No lint rule preventing hardcoded color/spacing/radius/shadow values. CLAUDE.md says "NEVER hardcode" — needs a stylelint or eslint rule that fails build. |
| Q5 | MED | `.dark` and `data-theme="aiox"` specificity rules documented in comments but not in a central design doc (until now — see DESIGN.md). |
| Q6 | LOW | Storybook config uses `@storybook/addon-a11y` — good. But no documented gate "story must pass a11y addon before merge". |
| Q7 | LOW | `package.json` has both `vite-plugin-pwa` and a service worker / Workbox stack — service worker scope and theme assets (TASAOrbiter font URLs) need a registered cache strategy review. |
| Q8 | LOW | No visual regression testing (Chromatic addon installed `@chromatic-com/storybook` but unclear if active). |

### Recommendations

- Split `aiox.css` Tier 5b into `themes/aiox-tailwind-remap.css` and **mark it deprecated** with a sunset plan.
- Add stylelint with `declaration-property-value-allowed-list` for color/spacing/radius/shadow → must be `var(--*)` only.
- Wire `validate-brandbook-tokens.ts` into pre-commit and CI.
- Add a11y addon gate to Storybook CI.
- Audit service worker cache strategy for fonts and theme CSS.
- Activate Chromatic for visual regression on PRs.

### Top 5 priorities (do these first)

1. **I1 — Standardize focus rings across themes** (CRIT, accessibility).
2. **C1/C2 — Resolve accent identity contradiction** (HIGH, brand integrity): pick one theme as canonical brand, document the other as variant.
3. **L1/L2 — Resolve dual spacing scales** (HIGH, foundation): deprecate `--spacing-*`, codemod to `--space-*`, decide 15px vs 16px base.
4. **C3/Q1/Q2 — Eliminate Tier 5b Tailwind remap** (HIGH, technical debt): forbid utility colors, lint enforce, delete remap block.
5. **Cm1/Cm2/Cm3 — Decouple components from theme** (HIGH, scalability): merge cockpit/glass parallel implementations into theme-driven variants.
