# CDM Portal — Product Context

> Baseline product documentation for the AIOS Platform Dashboard (codename: CDM Portal — Cockpit / Dashboard / Mission control).
> Generated by Uma (UX Design Expert) on 2026-05-06 from the live `aiox-dashboard` codebase.

---

## Product Purpose

The **CDM Portal** is the operator UI for **AIOS Platform** — a system for orchestrating squads of AI agents that execute software development work end-to-end (story creation, implementation, QA, deployment).

It is a **mission-control surface**, not a marketing site. The user is here to:

- See what their AI workforce is doing **right now** (terminals, agents, status, costs).
- Steer the workflow (kanban of stories, command palette, chat with agents).
- Inspect outcomes (QA metrics, GitHub PRs, insights, world map of squads).
- Configure squads, MCPs, registries, knowledge bases, roadmap, voice mode.

Problem it solves: AI agents working in parallel produce a fog of activity (logs, terminals, PRs, costs, errors). Without a cockpit you cannot intervene, audit, or trust the system. CDM Portal turns that fog into a **single high-density operational view**.

## Users

| Persona | Context | Expertise |
|---|---|---|
| **AIOS Operator** (primary) | Indie engineer / small-team lead running the platform on their own projects. Spends hours/day in the portal. Needs density, keyboard control, no-friction context switching. | High — software engineer, comfortable with terminals, git, monitoring tools. |
| **Squad Lead** | Configures agents/squads, validates outputs, escalates blockers. | Medium-high — product/PM-leaning developer. |
| **Stakeholder / Observer** | Reads dashboards (cost, throughput, QA pass rate). Does not configure. | Low to medium — wants summary, not internals. |

Usage shape: **long sessions, high frequency, multi-monitor**. Not a "click once a week" SaaS — closer to a Bloomberg terminal for AI agent orchestration.

## Brand

- **Name:** AIOS Platform — CDM Portal (cockpit) / aliases: AIOX Cockpit theme.
- **Register:** **product** (operational tool — design SERVES the product, not the other way around). The interface should disappear once the operator is in flow.
- **Tone:**
  - Technical, precise, no-nonsense. Labels in `UPPERCASE WITH 0.08em LETTER-SPACING`.
  - Brutalist confidence — `border-radius: 0` on cockpit components, hard edges, monospaced labels.
  - Restrained neon — lime accents (`#D1FF00`) on near-black (`#050505`), used sparingly for state and focus, never as decoration.
  - Honest density. We show numbers, statuses, and timestamps; we do not hide complexity behind cheerful illustrations.
- **Voice:**
  - Imperative, short. "Push", "Build", "Validate", "Stop QA Loop".
  - System messages report state, not feelings ("Story #42 transitioned: InReview → Done", not "Yay! Your story is done!").
  - Bilingual surface (PT / EN / ES / ZH) — copy must be terse enough to translate without reflowing layout.
- **Anti-references** (visual languages we explicitly reject):
  - Generic "purple/blue AI gradient" SaaS aesthetic (Linear, Notion AI, OpenAI marketing). We are operations, not chatbot demos.
  - Glassmorphism for its own sake. We use translucency only where it clarifies layering (overlays, modals, command palette). Cockpit theme intentionally **reduces** glass blur to ~10px and uses near-opaque surfaces.
  - "Hero metric + 3 identical card columns" landing-page layouts. Dashboards must respect spatial information density, not marketing rhythm.
  - Pure `#000000` backgrounds with neon. We use `#050505` and a layered void gradient with subtle lime + flare radial glows — depth, not theater.
  - Inter font everywhere. We use **TASAOrbiterDisplay** for display, **Geist** for sans, **Roboto Mono** for labels and code.
  - Generic Lucide/Feather icon-only system. We do use lucide-react, but cockpit components use brand-specific framing (HUD brackets, hazard stripes, dot-grids, bracket frames).
  - Confetti / celebration animations on routine actions. Reserved for genuine milestones (e.g., epic completion).

## Strategic Principles

Derived from the codebase architecture and existing token system:

1. **Tokens > components > pages.** Three-tier token system (`primitives → semantic → component`) enforced via `src/styles/tokens/`. Hardcoding colors, spacing, radius, shadow, or font is forbidden. The `aiox.css` theme demonstrates total token override without changing a single component.
2. **Theme is identity.** `data-theme="aiox"` flips the entire portal from default Liquid Glass to brutalist Cockpit by reassigning ~250 CSS variables. New themes must do the same — no new theme may patch components directly.
3. **Density first, decoration last.** Multi-panel layouts (sidebar + header + content + activity panel + status bar) carry information. Whitespace is structural, not aesthetic.
4. **Keyboard parity.** Every action reachable by pointer must be reachable by keyboard. Command palette (`⌘K`) is a first-class navigation surface, not a shortcut.
5. **Honest state, always visible.** Status dots, badges, progress bars, terminal feeds, agent monitor — the operator must always know what is running, queued, or stuck. Silent UI is broken UI.
6. **Local-first feel.** The dashboard talks to a local engine (`bun engine`) and Supabase. Latency tolerance is low; loading states must be skeleton-shaped (not blocking spinners) and complete <300ms in nominal path.
7. **Bilingual & accessible by default.** WCAG AA contrast minimum, every icon-only button has `aria-label`, every input has a label, every interactive element keyboard-focusable. PT-first copy with EN/ES/ZH parity.
8. **Storybook is contract.** Every UI primitive has a `.stories.tsx`. Components without stories are not part of the system.

## Anti-patterns to Avoid

### Visual
- Purple/blue "AI assistant" gradient as primary brand color.
- Three identical card columns as the dashboard hero ("metric A | metric B | metric C").
- Generic Lucide/Feather icons used decoratively (every icon must carry semantic weight).
- Pure `#000000` backgrounds in dark mode (use `#050505` with the layered void gradient).
- Inter / SF Pro everywhere — display headings must use **TASAOrbiterDisplay**, labels **Roboto Mono**.
- Rounded corners on cockpit components (`border-radius: 0` is the rule for `data-theme="aiox"`).
- Decorative glassmorphism. Translucency only for genuine layering.

### Copy
- Marketing voice ("Welcome back! Let's get started!").
- Vague status ("Loading...", "Something went wrong"). Always specify what and what to do next.
- Emoji decorations in system messages.
- Untranslated strings hardcoded in JSX.

### Interaction
- Modal dialogs for actions that should be inline (use slide-overs / popovers / command palette).
- Confirmation dialogs for non-destructive actions.
- Hover-only affordances (must work on keyboard focus too).
- Auto-redirect on state change without user acknowledgment.

### Architecture
- Hardcoded color/spacing/radius/shadow/font values.
- New components without Storybook stories.
- Tailwind utility colors (`bg-blue-500`, `text-purple-600`) outside the token system — these get globally remapped in `aiox.css` Tier 5b, but the practice is fragile.
- New CSS variables added directly to `liquid-glass.css` instead of the token tier files.
- New themes implemented by overriding components instead of overriding token variables.
